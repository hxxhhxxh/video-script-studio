# 视频链接 → 改写剧本 · 人物画像 · 分镜提示词

丢一个视频链接进去，自动跑完：**下载音轨 → 语音转文字 → 提炼节拍 → 改写剧本 → 人物画像（年龄/性别/穿戴/配饰）→ 分镜表（时长 + 生成提示词 + 负向提示词 + 字幕 + 音效）**。

全程本地跑，不需要任何 API key。

## 两种用法

### 一、本机直用（最简单）

浏览器打开 <http://127.0.0.1:8790>，不需要任何设置。

### 二、公网前端 + 本机后端（GitHub Pages）

前端页面挂在 GitHub Pages 上，网址永久且固定，计算仍在你电脑上跑：

1. 打开 <https://hxxhhxxh.github.io/video-script-studio/>
2. 展开页面上部的「后端设置」
3. 后端地址填你的后端域名（例如 `https://xxxxx.ts.net`），口令填后端 `.access-token.txt` 里的值
4. 点保存，之后浏览器会记住

也可以直接用带参数的链接跳过第一次配置：

```
https://hxxhhxxh.github.io/video-script-studio/static/index.html?backend=https://你的后端域名
```

口令仍需手动填一次（不会写进网页，也不会进仓库）。

**注意**：这种模式依赖你电脑开机；电脑关了就访问不了。要彻底不依赖电脑，看“部署到服务器.md”。

## 启动

```powershell
cd C:\Users\hxxhz\lobsterai\project\video-script-studio
python app.py
```

浏览器打开 <http://127.0.0.1:8790>

## 流水线各环节用的东西

| 环节 | 默认实现 | 换成别的 |
|------|----------|----------|
| 链接解析 / 下载 | yt-dlp（支持抖音、B站、小红书、YouTube 等） | `pipeline.download_media()` |
| 语音识别 | faster-whisper（本地 CPU，int8 量化） | `pipeline.transcribe()` |
| 剧本 / 人物 / 分镜 | 本地 Ollama `deepseek-r1:8b` | 见下面"接云端模型" |
| 提示词配方 | `prompts.py` 里的中文指令 | 直接改这个文件 |

## 接云端模型（可选，速度快很多）

不设环境变量就用本地 Ollama。想换成任意 OpenAI 兼容接口（DeepSeek / 硅基流动 / 阿里百炼 等）：

```powershell
$env:VSS_LLM_BASE_URL = "https://api.deepseek.com/v1"
$env:VSS_LLM_API_KEY  = "你的key"
$env:VSS_LLM_CLOUD_MODEL = "deepseek-chat"
python app.py
```

密钥只从环境变量读，不写进任何文件。

## 其他可调参数（环境变量）

| 变量 | 默认 | 说明 |
|------|------|------|
| `PORT` | 8790 | 端口 |
| `VSS_OLLAMA` | http://127.0.0.1:11434 | Ollama 地址 |
| `VSS_LLM_MODEL` | deepseek-r1:8b | 本地模型名 |
| `VSS_WHISPER` | small | 语音模型档位 |
| `VSS_NUM_CTX` | 8192 | 上下文窗口 |
| `VSS_CHUNK_CHARS` | 1200 | 转录分块字数（越大越快、越吃上下文） |

## 产出物

每次任务在 `runs/<时间戳>/` 下落三份文件：

1. `result.json` —— 完整结构化数据
2. `result.md` —— 可读文档（剧本 + 人物 + 分镜表 + 转录）
3. `storyboard.csv` —— 分镜表（可直接进 Excel，含所有提示词列）

页面右上也有三个下载按钮，以及对每个镜头的「中文/EN」一键复制。

## 关于速度（实测，2026-09-17 本机）

| 环节 | 实测数据 |
|------|----------|
| 语音识别（模型已缓存） | 30 秒中文音频 → 140 字，4 秒 |
| 首次下载语音模型 | 141 秒（约 460MB，从 hf-mirror 取，只一次） |
| 分段提炼（156 字样例） | 75 秒 → 7 个节拍 |
| 写剧本 | 63 秒 → 7 场 |
| 人物画像 | 59 秒 → 3 个角色 |
| 分镜 + 提示词 | 216 秒 → 8 个镜头 |
| **全链路** | **412 秒，产出 8 镜头 / 65 秒 / 3 人物** |

真实视频（1–3 分钟口播）预计 8–15 分钟。

### 两个必须知道的工程坑（已内置解法）

1. **不能让模型一次吐完**。"剧本 + 人物 + 全部分镜"塞进一个 JSON 时，本地模型会在输出上限处被截断（实测 7592 字处断掉，JSON 非法）。所以总装已拆成三次独立调用（剧本 / 人物 / 分镜）。
2. **R1 系列关不掉“思考”**。`think:false` 与空思考块预填都试过，无效；一次小小的节拍提取就能烧掉 3000 token。结构化任务建议用非思考模型，或直接走云端。

### 模型选择的现实

| 方案 | 速度 | 质量 |
|------|------|------|
| 本地 `deepseek-r1:8b`（默认） | 慢（单次调用 5 分钟起） | 文笔好，但易被输出上限截断 |
| 本地 `qwen2.5-coder:7b` | 中（全链约 7 分钟） | 勉强可用，提示词有重复堆砌 |
| 云端 DeepSeek（推荐） | 快（同流程约 30–60 秒） | 明显更好 |

切本地模型：`$env:VSS_LLM_MODEL="qwen2.5-coder:7b"; python app.py`

## 已知边界

1. 抖音的部分链接需要登录态，yt-dlp 可能抓不到，换 B站/小红书或直接给可访问的直链。
2. 纯音乐、无人声的视频会在转录后报错退出（这是预期行为）。
3. 分镜时长被约束成 5 秒或 10 秒两档，对齐主流 AI 视频模型；总时长贴近你设的目标值但不保证完全相等。
4. 人物外观靠 `anchor_cn` 锚定，多镜头一致性受生成模型本身限制，真人特写建议先转素描再生成。
